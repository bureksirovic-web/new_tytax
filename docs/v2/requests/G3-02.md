# G3-02: seeded/imported history carries no PR records, so the first PR after it is a "baseline" (owner: G2, fixture G5)

**What:** `repo.finishWorkout` compares against stored `prRecords` only (`src/lib/db/repo/finish.ts`, `existingBests`).
`window.__tytaxE2E.seedHistory` writes logs through `importBackup` with `prRecords: []`. After seeding bench 100 × 5,
a new workout with bench 120 × 5 is stored as a baseline and is not celebrated. The legacy spec says a PR is "e1RM > historical max",
where history means the logs.

**Impact:** any path that brings logs without PR records (e2e seeding; a backup or migration that omits `prRecords`) under-reports the first PR after it.

**Workaround in G3:** `e2e/pr.spec.ts` sets the previous best with a real finished workout through the UI.

**Proposed fix (one of):**
1. `seedHistory` (G5, `e2e-hooks.ts`) also writes the PR records `training.detectPRs` would derive for the seeded logs; or
2. `importBackup`/migration (G2) rebuilds `prRecords` from imported logs when the backup has none.
