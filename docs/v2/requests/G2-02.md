# G2-02: settings UI wiring for backup, import and export (to G4)

**Owner of the change:** G4 (`src/app/(app)/settings/**`, `src/components/settings/**`).
**Blocking:** no. G2's services are finished and tested; only the buttons are missing.

## APIs to call (all from G2, all tested)
| UI action | Call |
|---|---|
| Legacy import: preview | `previewLegacyImport(text)` from `@/lib/import/service` |
| Legacy import: run | `importLegacy(repo, text, { users: [{ username, target: { profileId } \| { createProfileName } }] })` |
| JSON backup download | `exportBackupJson(repo, profileId?)` → download as `tytax-backup-YYYY-MM-DD.json` |
| JSON restore: confirm step | `inspectBackupJson(repo, text)` → **ask before merging** when `existingProfileIds` is non-empty (see the unfixed finding in G2-REPORT: a hostile file can overwrite an existing profile once) |
| JSON restore: run | `restoreBackupJson(repo, text)` |
| CSV export | `workoutLogsToCSV(logs, { units })`, `bodyweightToCSV(entries, { units })`, `downloadCSV(content, filename)` from `@/lib/export/csv` |
| Pre-migration backup (v2 users) | `getPreMigrationExport(getDb())` from `@/lib/db/migrations`; if not null, offer a download, then `clearPreMigrationExport(getDb())` on user confirmation |

Errors: `ImportError.code` (`TOO_LARGE`, `INVALID_JSON`, `UNSAFE_KEYS`, `UNRECOGNIZED_FORMAT`, `INVALID_STRUCTURE`) and `RepoError.code` (`VALIDATION`, `NOT_FOUND`, `CONFLICT`, `STORAGE`). Map codes to i18n messages; never show `message` raw.

## i18n
G2 adds no UI strings. G4 owns the keys for these screens.
