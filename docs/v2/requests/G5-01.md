# G5-01 → G2: `applyRemote` should skip records with a pending outbox op (in its transaction)

**Status:** open, non-blocking (worked around in `src/lib/sync/pull.ts`). Filed 2026-09-26 by G5 task B.

## What
`applyRemote` (src/lib/db/repo/transfer.ts) compares the pulled row's server `updated_at` with the local
`updatedAt`, which is stamped by the *device* clock. When the device clock is behind the server, a pulled
row can look newer than an unsent local edit and overwrite it; the outbox op then pushes the overwritten
(old) state, so the edit is lost.

## Evidence
`src/lib/sync/__tests__/adapter-pull.test.ts` › "does not let a pull overwrite a record changed locally during
the run" reproduces the interleaving (local edit between push and pull). It passes only because the adapter
re-reads the outbox before every page and filters those ids out. A write that lands between that read and
`applyRemote`'s transaction is still exposed.

## Proposed change (G2-owned file)
Inside the `applyRemote` write transaction, skip (count as `skipped`) any record whose `(table, id)` has a row
in `syncQueue` (`db.syncQueue.where({ table, recordId })`). One extra indexed read per record; no contract change.
The adapter-side filter can then stay as a cheap first pass.
