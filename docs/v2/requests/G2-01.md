# G2-01: profile switch/remove in `E2EHooks` (to G5)

**Owner of the change:** G5 (`src/contracts/fixtures.ts` is frozen; `src/components/providers/e2e-hooks.ts` and `e2e/fixtures/**` are G5's).

## Why
AC9 (persistence) needs an e2e that switches the active profile and deletes a
profile. `window.__tytaxE2E` (`E2EHooks`) can seed profiles but cannot switch
or delete one, and the profile UI (G4, `profiles-ui.spec.ts`) is not merged.

## Requested (additive, optional)
In `E2EHooks` (`src/contracts/fixtures.ts`):

```ts
/** repo.profiles.setActive(id). */
setActiveProfile?(profileId: string): Promise<void>;
/** repo.profiles.remove(id): wipes only that profile's data. */
removeProfile?(profileId: string): Promise<void>;
/** repo.profiles.list(). */
listProfiles?(): Promise<Profile[]>;
```

Implement them in `createE2EHooks` (one line each, straight to the repository)
and mirror them in `TytaxFixture` (`e2e/fixtures/seed.ts`).

## Interim hook (already in v2-g2)
`src/lib/db/index.ts` sets `window.__tytaxRepo` to the app repository when
`getRepository()` first constructs it, under the same guard `AppBootstrap` uses
for `__tytaxE2E` (`NODE_ENV !== 'production' || NEXT_PUBLIC_E2E_HOOKS === '1'`).
It is typed by a `declare global` in `src/lib/db/index.ts`, not in contracts.
`e2e/profiles.spec.ts` calls `window.__tytaxRepo.profiles.{setActive,remove,list}`
through `page.evaluate`.

## After G5 lands this
G2 (or G5 at integration) switches `e2e/profiles.spec.ts` to the new fixture
methods; `window.__tytaxRepo` may then be removed or kept as a debugging aid.
