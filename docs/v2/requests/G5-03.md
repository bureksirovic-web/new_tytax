# G5-03: service worker must not intercept cross-origin requests (public/sw.js, owned by G4)

**From:** G5 (task D, sync wiring), 2026-09-26. **To:** G4 (`public/**`); G5 applies it at INTEGRATION if still open.

## What
`public/sw.js` answers every GET that is not `/api/*`, `/_next/static/*` or a navigation with
"network-first, then cache", and it does not check the origin. So every Supabase REST pull
(`GET https://<project>.supabase.co/rest/v1/<table>?…`, sent with the user's JWT) goes through the
service worker and:
1. **Privacy:** the authenticated response body (the user's workout logs, bodyweight, notes…) is
   written to Cache Storage (`CACHE_NAME`) keyed by URL, and stays there after sign-out, on a
   possibly shared device.
2. **Sync correctness:** when the network fails, the worker answers with the cached (old) page for
   the same URL instead of a network error, so a pull can "succeed" with stale rows.
3. **Local/CI breakage:** the worker's fetch runs under the worker script's own CSP (next.config.ts
   `connect-src`, see G5-02), so against a non-`*.supabase.co` Supabase every pull fails with
   `net::ERR_FAILED` once the worker controls the page.

## Evidence
`e2e/sync-roundtrip.spec.ts`, first run with sync on (2026-09-26), Playwright trace network log:

    GET  http://127.0.0.1:54421/rest/v1/family_members?select=*&order=…            200   (before the SW took control)
    POST http://127.0.0.1:54421/rest/v1/workout_logs?on_conflict=id…               201   (non-GET: not intercepted)
    GET  http://127.0.0.1:54421/rest/v1/family_members?select=*&updated_at=gte.…   net::ERR_FAILED  (x12, via the SW)

The adapter then reports `network` and backs off (2 s, 4 s, 8 s …); the sync never completes.

## Proposed change (one line, first thing in the fetch handler)
```js
self.addEventListener('fetch', (event) => {
  const { request } = event;
  const url = new URL(request.url);
  // Same-origin only: never touch Supabase or any other cross-origin request (auth, data, fonts).
  if (url.origin !== self.location.origin) return;
  …
```
Bump `CACHE_NAME` in the same change so the activate handler drops caches that may already hold
Supabase responses.

## Workaround until applied
`e2e/sync-roundtrip.spec.ts` runs with `serviceWorkers: 'block'` (comment names this file). Remove
it when this request is applied; the spec must then still pass.
