# G5-07: `E2EHooks` boot state: `ready: boolean` and optional `bootError` (src/contracts/fixtures.ts, frozen)

**From:** G5 (WAVE0_REVIEW S3-05), 2026-09-27. **To:** integration (G5 applies it; `src/contracts/**` is frozen in the worktrees).

## What
`AppBootstrap` now installs `window.__tytaxE2E` *before* `repo.profiles.ensureActive()`, so a failed boot
still exposes `reset()` and the error. `ready` is `false` while booting and flips to `true` after
`ensureActive`; on failure `bootError` carries the message and `waitForApp()` / `tytax.gotoApp()`
(`e2e/fixtures/seed.ts`) throw it instead of timing out.

The contract says `readonly ready: true` and has no `bootError`, so G5 works behind a local type:
`E2EBootHooks` in `src/components/providers/e2e-hooks.ts` (assigned with `hooks as E2EHooks`), and
`e2e/fixtures/seed.ts` reads the window object as `{ ready?: boolean; bootError?: string }`.

## Proposed change (at integration)
```ts
export interface E2EHooks {
  /** false while the app boots; true once an active profile exists. */
  readonly ready: boolean;
  /** Set when the boot failed; e2e waits throw it. */
  readonly bootError?: string;
  // …rest unchanged
}
```
Then: drop `E2EBootHooks`' `Omit` (make it `E2EHooks` with mutable `ready`/`bootError`), remove the
`as E2EHooks` cast in `installBootingE2EHooks`, and the cast in `waitForApp`.
Every existing consumer compares `ready === true`, so widening `true` to `boolean` breaks none of them
(`grep -rn "__tytaxE2E" src e2e`).

## Why not now
`src/contracts/**` is frozen in the G worktrees during the overnight run.
