# G5-06: Settings account section: hide it when sync is off, or use the sync panel (src/components/settings, owned by G4)

**From:** G5 (refuter fixes), 2026-09-27. **To:** G4 (`src/components/settings/**`, `src/app/(app)/settings/**`).

## What
`src/components/settings/account-section.tsx` renders a sign-in / sign-out UI on every Settings visit,
also with `NEXT_PUBLIC_SYNC_ENABLED` unset, next to `SyncStatus`, which already shows the account
(`src/components/sync/sync-account.tsx`). Before the G5 fix below it also loaded supabase-js and, with a
stale session cookie, called `/auth/v1/token?grant_type=refresh_token` on every visit.

## Evidence
`src/components/providers/__tests__/settings-flag-off.test.tsx` (Providers + SettingsPage, flag unset,
Supabase env set, stale `sb-127-auth-token` cookie, real supabase-js). With the old `src/lib/auth/helpers.ts`:
`expected [ "http://127.0.0.1:54421/auth/v1/token?grant_type=refresh_token" ] to deeply equal []`.
esbuild static graph of `src/app/(app)/settings/page-client.tsx`: old helpers pull
`@supabase/supabase-js`, `auth-js`, `ssr`, `functions-js`, …; now none.

## Fixed in G5 (in place)
`getSession()` and `signOut()` in `src/lib/auth/helpers.ts` return at once unless sync is on
(`isSyncEnabled()` in `src/lib/supabase/env.ts`), and load the Supabase client with a dynamic `import()`.

## Proposed change (G4)
Either render nothing when sync is off:
```tsx
import { isSyncEnabled } from '@/lib/supabase/env';
export function AccountSection() {
  if (!isSyncEnabled()) return null;
  // …as today
}
```
or delete `AccountSection` and let the Settings page rely on `SyncStatus` / the sync panel, which already
renders the account and loads supabase-js only on demand. `settings/__tests__/page-client.test.tsx`
expects the `settings-account` test id; update it with the change.
