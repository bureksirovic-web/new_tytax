# G2-W2-01: machine setup on the NotesRepo contract (to the contract owner / G5)

**Blocking:** no. Implemented behind `NotesRepoExt` (`src/lib/db/repo/notes.ts`), reachable via `getNotesExt(repo)` from `@/lib/db`.

## Proposed contract addition (src/contracts/repo.ts, additive)
```ts
export interface NotesRepo {
  // ...existing get / set / list
  /** Live note's machine setup, or undefined. */
  getSetup(profileId: string, exerciseId: string): Promise<MachineSetup | undefined>;
  /** Replaces the setup; null or {} clears it. */
  setSetup(profileId: string, exerciseId: string, setup: MachineSetup | null): Promise<ExerciseNote | undefined>;
}
```
and the doc comment on `set` changes from "an empty string soft-deletes the note" to
"an empty string soft-deletes the note unless it still has a setup (then content becomes '')".

## Semantics (implemented, tested in src/lib/db/__tests__/w2-misc-notes-setup.test.ts)
- Validation: plain object; only `seat, pin, backrest, benchAngle, cable, other`; each value a string, trimmed, 1..40 chars; `undefined` values ignored; anything else is `RepoError('VALIDATION')`.
- A note is live while it has content OR a setup. `setSetup(.., null)` on a note with empty content soft-deletes it.
- `setSetup` replaces the whole setup (no field merge). A revived tombstone does not bring back its old content or setup.
- Round-trip: `exportBackup` → `importBackup` keeps `setup`. `restoreBackupJson` does NOT until the backup-v3 schema change below lands.
