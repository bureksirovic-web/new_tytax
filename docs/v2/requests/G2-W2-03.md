# G2-W2-03: `EquipmentInventory.configuredAt?: string` (to the contract owner / G5)

**Blocking:** no. Until it lands, `isEquipmentConfigured(inv)` from `@/lib/db` is the rule.

## Problem
`equipment.get` returns an empty default when nothing is stored, so the UI cannot tell "never set up" from "owns nothing". Today the helper answers `false` only when all four lists (`stationIds`, `attachmentIds`, `kettlebellsKg`, `bodyweightGear`) are empty. A user who deliberately saves an empty inventory still reads as "not configured" (bodyweight-only users can save `bodyweightGear: ['none']` to count as configured).

## Proposed contract addition (domain.ts, additive, optional)
```ts
export interface EquipmentInventory {
  // ...
  /** Set by equipment.save the first time; absent = never configured. */
  configuredAt?: string;
}
```
Then `equipment.save` stamps it once, the backup-v3 `equipmentInventorySchema` gains `configuredAt: timestamp.optional()`, and `isEquipmentConfigured` becomes `inv.configuredAt !== undefined || <lists non-empty>` (the list rule keeps pre-existing rows configured).
