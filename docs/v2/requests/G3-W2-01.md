# G3-W2-01: machine-setup writer on the notes repository (to G2)

**From:** G3 (workout loop), Wave 2 item 3. **To:** G2 (persistence). **Severity:** S3 (the feature degrades to read-only without it).

## What
The frozen `NotesRepo` (`src/contracts/repo.ts`) has `get / set(content) / list`; `set` cannot write
`ExerciseNote.setup`. G3 shows the setup on each exercise card and offers a quick-edit sheet, so it needs a writer.

## Requested (repository implementation, no contract change needed)
On the object returned as `repo.notes` (preferred) or on the repository itself:

```ts
/** Upserts the note row's `setup` for (profileId, exerciseId); `undefined` clears it. Keeps `content`.
 *  Creates a live note with `content: ''` when none exists (the setup alone must be storable; `set('')`
 *  soft-deleting must not drop a row that still carries a setup). Queues the sync outbox like `set`. */
setSetup(profileId: string, exerciseId: string, setup: MachineSetup | undefined): Promise<ExerciseNote | undefined>;
/** Convenience (already planned by G2, Wave 2 item 5). */
getSetup(profileId: string, exerciseId: string): Promise<MachineSetup | undefined>;
```

## How G3 consumes it
`src/stores/setup-adapter.ts` duck-types `notes.setSetup` → `repo.setSetup` for writing and `notes.getSetup` →
`repo.getSetup` → `notes.get(...)?.setup` for reading. Values arrive trimmed, each field ≤ 60 chars, empty fields
dropped, `undefined` when nothing is left. Until a writer exists `saveSetup` returns
`{ saved: false, reason: 'unsupported' }` and the UI shows the setup read-only. If G2 picks another method name,
tell G5 at integration; the adapter change is one line in `writerOf`.
