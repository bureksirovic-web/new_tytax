# G5-02: CSP `connect-src` must allow the configured Supabase origin (next.config.ts, frozen)

**From:** G5 (task D, sync wiring), 2026-09-26. **To:** whoever may edit `next.config.ts` (G5 at INTEGRATION).

## What
`next.config.ts` sends `connect-src 'self' https://*.supabase.co ws://localhost:* ws://127.0.0.1:*`.
The browser talks to Supabase directly (docs/v2/sync-schema.md, "One sync path"), so any Supabase
that is not `https://*.supabase.co` is blocked: the local stack (`http://127.0.0.1:54421`, used by
`npm run dev` with sync on, the CI `sync-e2e` job and `scripts/ci-local.sh`), and any self-hosted
or custom-domain Supabase.

## Evidence
`PORT=3105 NEXT_PUBLIC_SYNC_ENABLED=true … npx playwright test e2e/sync-roundtrip.spec.ts`, browser console
(trace of the first run, 2026-09-26):

    Connecting to 'http://127.0.0.1:54421/auth/v1/otp?redirect_to=…' violates the following Content Security
    Policy directive: "connect-src 'self' https://*.supabase.co ws://localhost:* ws://127.0.0.1:*".
    The action has been blocked.

The login form then shows `auth.error.send_failed`; sign-in and every sync request are impossible.

## Proposed change (additive; production value unchanged when the URL is *.supabase.co)
```ts
function supabaseConnectSrc(): string {
  const raw = process.env.NEXT_PUBLIC_SUPABASE_URL?.trim();
  if (!raw) return '';
  try {
    const u = new URL(raw);
    if (u.protocol !== 'https:' && u.protocol !== 'http:') return '';
    const ws = `${u.protocol === 'https:' ? 'wss' : 'ws'}://${u.host}`;
    return ` ${u.origin} ${ws}`;
  } catch {
    return '';
  }
}
// connect-src 'self' https://*.supabase.co${supabaseConnectSrc()} ws://localhost:* ws://127.0.0.1:*
```
`NEXT_PUBLIC_SUPABASE_URL` is read when the config loads (build / `next dev` start), the same moment
the NEXT_PUBLIC_* values are inlined, so the CSP always matches the bundle's Supabase URL.

## Workaround until applied
`e2e/sync-roundtrip.spec.ts` sets `test.use({ bypassCSP: true })` with a comment naming this file.
Nothing else is affected: `e2e/auth-callback.spec.ts` never calls Supabase from the browser.
Remove the `bypassCSP` line in the same change that applies this request (the spec must then still pass).
